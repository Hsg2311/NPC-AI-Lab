# 중간보스 지휘 기반 Tactical NPC 전술 시스템 보고서 초안

> 작성 대상: 졸업작품 보고서 본문 초안  
> 구현 대상: `ScenarioTactical`, `PlatoonLeader`, `TacticalSquad`, `TacticalNpc`  
> 작성일: 2026-05-07

## 1. 개요

본 프로젝트는 다수의 NPC가 플레이어를 단순히 개별 추적하는 방식에서 벗어나, 중간보스의 지휘에 따라 Squad 단위로 대형을 형성하고 전술 조건에 따라 포위 전술을 수행하는 전술 NPC 시스템을 구현하는 것을 목표로 한다. 일반적인 추적 AI는 NPC 수가 증가할수록 서로 겹치거나 동일한 경로로 몰리는 문제가 발생하며, 플레이어 입장에서도 전투 양상이 단조롭게 느껴질 수 있다. 이를 개선하기 위해 본 시스템은 NPC를 개별 객체로만 제어하지 않고, 중간보스-분대-개별 NPC의 계층형 구조로 설계하였다.

시뮬레이션이 시작되면 중간보스는 3개의 Squad에 초기 대형 명령을 내려 플레이어 전방에 박스형 대형을 형성하도록 한다. 이 대형이 완성되면 Squad는 플레이어를 추적하는 Engage 상태로 전환된다. 이후 중간보스의 체력이 일정 비율 이하로 감소하거나 Squad의 생존 인원이 일정 비율 미만으로 줄어드는 전술 조건이 충족되면, 중간보스는 포위 전술을 발동한다. 포위 전술에서는 전체 NPC 수와 Squad별 인원 비율을 고려하여 원형 섹터를 배분하고, 각 NPC가 자신에게 할당된 슬롯으로 이동하여 플레이어 주변을 둘러싼다.

본 시스템의 핵심은 전술 판단과 개별 이동을 분리했다는 점이다. 중간보스는 전술 선택을 담당하고, Squad는 전술 명령을 실제 월드 좌표상의 대형 슬롯으로 변환하며, 개별 TacticalNpc는 명령을 소비해 FSM 기반 이동과 공격을 수행한다. 이를 통해 다수의 NPC를 일일이 직접 제어하지 않고도 조직적인 전술 행동을 구현할 수 있었다.

## 2. 개발 배경 및 문제 정의

기존의 단순 NPC 추적 방식은 각 NPC가 독립적으로 플레이어를 향해 이동하는 구조이다. 이 방식은 구현이 단순하지만, NPC 수가 증가하면 다음과 같은 문제가 나타난다.

첫째, 여러 NPC가 동일한 목표점인 플레이어 위치로 동시에 이동하기 때문에 NPC끼리 겹치거나 좁은 영역에 과도하게 몰린다. 둘째, 모든 NPC가 같은 판단 기준으로 움직이기 때문에 전투 양상이 단조롭고, 플레이어가 NPC 집단의 의도를 읽기 어렵다. 셋째, 전투 상황에 따라 후퇴, 경계, 포위와 같은 집단 전술을 표현하기 어렵다.

본 프로젝트에서는 이러한 문제를 해결하기 위해 NPC를 Squad 단위로 묶고, 중간보스가 전체 전투 흐름을 지휘하는 구조를 채택하였다. 이 구조에서는 개별 NPC가 직접 전술을 판단하지 않는다. 대신 중간보스가 전술 조건을 평가하고, Squad는 중간보스의 명령을 위치 기반 대형으로 변환하며, 각 NPC는 자신에게 할당된 슬롯 또는 타겟을 향해 행동한다.

## 3. 시스템 구조

전술 NPC 시스템은 3계층 구조로 구성된다.

```text
PlatoonLeader
  전술 판단 및 Squad 지휘
  └─ SquadOrder

TacticalSquad
  SquadOrder를 슬롯 좌표와 개별 명령으로 변환
  └─ TacticalCommand

TacticalNpc
  개별 이동, 공격, 대기 FSM 실행
```

### 3.1 PlatoonLeader

`PlatoonLeader`는 중간보스 역할을 수행한다. 일반 NPC처럼 직접 플레이어를 추적하고 공격하는 객체라기보다, 전투 상황을 평가하고 Squad에 명령을 내리는 지휘관에 가깝다. 주요 역할은 다음과 같다.

- 살아 있는 플레이어 중 주 타겟 선택
- Squad 생존 인원 관리
- 초기 BoxAdvance 대형 발행
- 전술 발동 조건 검사
- 포위, 경계, 각개격파 페이즈 전환
- Squad에 `SquadOrder` 발행

### 3.2 TacticalSquad

`TacticalSquad`는 실제 월드에 존재하는 Actor가 아니라, 여러 TacticalNpc의 ID를 보유하는 지휘 보조 객체이다. 중간보스에게서 받은 `SquadOrder`를 해석하여 각 NPC가 이동해야 할 슬롯 좌표를 계산하고, 개별 NPC에게 `TacticalCommand`를 전달한다.

예를 들어 중간보스가 `Encircle` 명령을 내리면 Squad는 자신의 섹터 각도와 반경을 기준으로 포위 슬롯을 생성한다. 이후 각 NPC와 슬롯 간 거리를 계산하여 가장 가까운 슬롯을 할당하고, NPC에게 `HoldSlot` 명령을 전달한다.

### 3.3 TacticalNpc

`TacticalNpc`는 개별 전투 유닛이다. 스스로 전술을 판단하지 않고, Squad가 전달한 명령을 `pendingCmd_`에 저장했다가 다음 업데이트 시점에 소비한다. 이후 현재 상태에 따라 이동, 추적, 공격 준비, 공격 회복, 슬롯 유지 등의 행동을 수행한다.

TacticalNpc의 주요 상태는 다음과 같다.

| 상태 | 의미 |
|---|---|
| `Idle` | 명령 대기 |
| `Chase` | 타겟 추적 |
| `AttackWindup` | 공격 준비 |
| `AttackRecover` | 공격 후 회복 |
| `Flank` | 지정 슬롯까지 이동 후 교전 |
| `HoldSlot` | 지정 슬롯까지 이동 후 위치 유지 |
| `Return` | 스폰 위치 복귀 |
| `Dead` | 사망 |

## 4. 시뮬레이션 흐름

시뮬레이션은 `Room::tick(dt)`에서 일정한 순서로 갱신된다. 전술 NPC와 관련된 핵심 순서는 다음과 같다.

```text
1. Player 업데이트
2. 캐시 재구성
3. PlatoonLeader 업데이트
4. TacticalSquad 업데이트
5. TacticalNpc 업데이트
```

이 순서는 중요하다. 중간보스가 먼저 전술 판단을 수행하고, 그 결과를 Squad가 개별 명령으로 변환한 뒤, 같은 틱에서 NPC들이 명령을 소비할 수 있기 때문이다. 따라서 지휘-대형 계산-개별 실행이 하나의 업데이트 흐름 안에서 자연스럽게 이어진다.

## 5. 초기 Squad 대형: BoxAdvance

시뮬레이션 시작 시 중간보스는 `BoxAdvance` 대형을 활성화한다. 이 대형은 3개의 Squad가 플레이어 전방에 박스형 또는 호형에 가까운 대형을 형성하도록 하는 초기 전술이다.

초기 대형에서 중요한 설계는 **대형 목표점 고정**이다. 플레이어는 시뮬레이션 도중 계속 움직일 수 있기 때문에, 대형 목표점을 매 프레임 현재 플레이어 위치로 다시 계산하면 NPC들이 계속 새로운 위치를 향해 이동하게 된다. 이 경우 대형 완료 판정이 지연되거나 완료되지 않는 문제가 발생할 수 있다.

이를 해결하기 위해 `BoxAdvance`는 명령 발행 시점의 플레이어 위치를 `formationTargetPos`로 저장한다. Squad는 이 고정 좌표를 기준으로 슬롯을 계산하며, 플레이어가 이후 이동하더라도 이미 발행된 슬롯은 재계산하지 않는다.

```text
P0 = BoxAdvance 명령 발행 시점의 플레이어 위치
B  = 중간보스 위치
```

플레이어 방향 벡터와 우측 벡터는 다음과 같이 계산한다.

```text
f = normalize(P0 - B)
r = (-fz, 0, fx)
```

각 Squad의 중심점은 다음 식으로 계산된다.

```text
C_s = P0 - f * d_approach + r * offset_x - f * offset_z - f * halfDepth
```

여기서 `d_approach`는 플레이어 전방에서 얼마나 떨어져 대형을 만들 것인지를 나타내는 거리이며, 현재 구현에서는 `BOX_APPROACH_DIST = 20`을 사용한다. `offset_x`와 `offset_z`는 Squad 간 간격과 호형 배치를 위한 상대 오프셋이다.

이후 각 Squad 내부에서는 밀집 격자 대형을 생성한다.

```text
cols = ceil(sqrt(n))
rows = ceil(n / cols)
spacing = max(memberSeparationRadius, 1.2)

slot_i = C_s
       + r * (col - (cols - 1) / 2) * spacing
       + f * (row - (rows - 1) / 2) * spacing
```

NPC들이 각자의 슬롯에 도착하면 `allMembersArrived()`가 참이 되고, 중간보스는 BoxAdvance를 종료한 뒤 Squad에 `Engage` 명령을 내려 플레이어 추적 상태로 전환한다.

## 6. 타겟 선택 알고리즘

중간보스는 살아 있는 플레이어를 대상으로 점수를 계산하여 가장 높은 점수를 가진 플레이어를 주 타겟으로 선택한다. 현재 시나리오에서는 플레이어가 1명이므로 항상 P1이 선택되지만, 다수 플레이어 환경으로 확장할 수 있도록 점수식을 구성하였다.

타겟 점수는 거리 점수와 체력 점수를 결합한다.

```text
S(p) = 0.5 * 1 / (1 + ||B - p||)
     + 0.5 * (1 - HP(p) / HPmax(p))
```

여기서 `B`는 중간보스 위치, `p`는 플레이어 위치이다. 첫 번째 항은 거리가 가까울수록 높은 점수를 주고, 두 번째 항은 체력이 낮은 플레이어일수록 높은 점수를 준다. 두 요소를 같은 가중치로 결합하여, 가까우면서도 처치 가능성이 높은 타겟을 우선하도록 설계하였다.

## 7. 전술 발동 조건

초기 상태에서 전술은 잠겨 있다. 전술은 전투가 어느 정도 진행되어 중간보스 또는 Squad가 피해를 입었을 때 발동된다. 조건은 다음과 같다.

```text
HPboss / HPboss,max < 0.70
```

또는

```text
aliveSquadMembers / initialSquadMembers < 0.80
```

즉, 중간보스의 현재 체력이 최대 체력의 70% 미만이 되거나, 어느 Squad의 생존 인원이 초기 인원의 80% 미만으로 감소하면 전술이 해금된다. 이 조건은 전투 초반부터 강한 전술이 발동되는 것을 막고, 전투가 진행됨에 따라 중간보스가 더 조직적인 행동을 보이도록 하기 위한 장치이다.

## 8. 포위 전술

전술 조건이 충족되면 중간보스는 플레이어의 군집 상태를 판단한다. 플레이어가 하나의 군집으로 모여 있다고 판단되면 `Encircle` 페이즈에서 포위 전술을 발동한다.

포위 전술은 전체 NPC를 하나의 원형 대형으로 배치하는 것이 아니라, Squad별로 원의 섹터를 나누어 담당하게 한다. Squad의 생존 인원이 다를 수 있으므로, 각 Squad가 차지하는 섹터의 크기는 Squad 인원 비율에 따라 결정된다.

전체 생존 멤버 수를 `N`, Squad `s`의 생존 멤버 수를 `n_s`라고 하면 Squad가 담당하는 섹터 폭은 다음과 같다.

```text
sectorSpan_s = 2π * n_s / N
```

해당 Squad의 중심 각도는 다음과 같이 계산한다.

```text
sectorAngle_s = angleAccum + sectorSpan_s / 2
```

이후 Squad 내부의 각 NPC 슬롯은 섹터를 다시 균등 분할하여 계산한다.

```text
theta_i = sectorAngle_s - sectorSpan_s / 2 + (i + 0.5) * sectorSpan_s / n_s
slot_i = P + R * (cos(theta_i), 0, sin(theta_i))
```

여기서 `P`는 플레이어 위치, `R`은 포위 반경이다. 현재 구현에서는 `ENCIRCLE_RADIUS = 50`을 사용한다. `(i + 0.5)`를 사용하는 이유는 슬롯을 섹터 경계가 아니라 각 소구간의 중앙에 배치하기 위함이다. 이렇게 하면 인접 Squad의 슬롯이 경계에서 겹치는 문제를 줄일 수 있다.

포위 슬롯이 생성되면 Squad는 각 NPC에 가장 가까운 슬롯을 할당한다. 이는 greedy nearest-slot 방식으로 구현하였다.

```text
각 NPC에 대해:
  아직 사용되지 않은 슬롯 중 distance(npcPos, slot)이 가장 작은 슬롯 선택
```

이 방식은 최적 배정 알고리즘에 비해 계산이 단순하며, 실시간 시뮬레이션에서 충분히 빠르게 동작한다. 또한 NPC가 현재 위치에서 가까운 슬롯을 선택하므로 이동 경로가 과도하게 교차하는 현상을 줄일 수 있다.

## 9. 개별 NPC 이동 및 상태 전이

개별 TacticalNpc는 Squad가 전달한 명령을 기반으로 FSM을 실행한다. 예를 들어 `EngageTarget` 명령을 받으면 `Chase` 상태로 전환되어 플레이어를 추적하고, `HoldSlot` 명령을 받으면 지정된 슬롯으로 이동한 뒤 위치를 유지한다.

도착 판정은 다음과 같이 계산한다.

```text
arrived_i = ||pos_i - slot_i|| < separationRadius * 0.25
```

현재 시나리오에서 `separationRadius = 6`이므로, 슬롯까지의 거리가 1.5보다 작으면 도착한 것으로 판단한다.

추적 또는 슬롯 이동 중에는 NPC끼리 겹치는 현상을 줄이기 위해 분리력을 사용한다. 주변 NPC 위치를 `q_j`, 현재 NPC 위치를 `p`라고 할 때 분리력은 다음과 같이 계산된다.

```text
away_j = p - q_j
d_j = ||away_j||
strength_j = 1 - d_j / separationRadius
F_sep = Σ normalize(away_j) * strength_j
```

`Chase`나 `Flank` 상태에서는 이동 방향과 수직인 분리 성분만 사용한다. 이는 NPC가 목표 반대 방향으로 밀려나 추적이 느려지는 현상을 줄이기 위한 것이다.

```text
F_perp = F_sep - dir * dot(F_sep, dir)
moveDir = normalize(dir + F_perp * separationWeight)
```

## 10. 디버그 시각화 및 검증

본 프로젝트는 WinAPI와 GDI 기반의 2D 시각화 도구를 제공한다. `Room::buildSnapshot()`은 플레이어, 일반 NPC, TacticalNpc의 위치와 상태를 디버그 스냅샷으로 변환하고, 렌더러는 이를 화면에 표시한다.

전술 NPC 검증에는 다음 시각 정보가 활용된다.

- NPC 상태별 색상
- HP 바
- Boss 표시
- Squad ID
- NPC가 추적 중인 타겟
- 할당된 슬롯 위치
- NPC에서 슬롯까지의 방향선

초기 BoxAdvance 대형 검증에서는 플레이어를 이동시켜도 슬롯 마커가 최초 목표 위치에 고정되는지 확인하였다. 이를 통해 플레이어 이동으로 인해 대형 목표점이 계속 바뀌어 대형 완료가 지연되는 문제를 해결할 수 있었다.

포위 전술 검증에서는 전술 조건을 만족했을 때 Squad별 포위 슬롯이 생성되고, NPC들이 원형 대형을 향해 이동하는지 확인하였다. 또한 모든 생존 멤버가 슬롯에 도착하면 쿨타임으로 전환되는지 확인하였다.

## 11. 구현 결과

구현된 전술 NPC 시스템은 다음과 같은 결과를 보였다.

첫째, 중간보스가 Squad 단위로 대형 명령을 내릴 수 있게 되었다. 이로 인해 개별 NPC를 직접 제어하지 않아도 다수의 NPC가 하나의 전술 의도를 가진 것처럼 움직일 수 있었다.

둘째, 초기 BoxAdvance 대형에서 목표 위치를 고정하여 플레이어 이동에 따른 슬롯 재계산 문제를 해결하였다. NPC들은 플레이어가 움직이더라도 최초 대형 목표점으로 이동하며, 대형이 완성되면 Engage 상태로 전환된다.

셋째, 전술 조건이 충족되면 중간보스가 포위 전술을 발동하도록 구성하였다. 포위 슬롯은 Squad 인원 비율에 따라 섹터를 나누어 계산되며, 각 NPC는 가까운 슬롯에 배정된다.

넷째, 전술 판단, 대형 계산, 개별 FSM 실행을 분리함으로써 추후 새로운 전술을 추가하기 쉬운 구조를 마련하였다. 예를 들어 후퇴, 측면 기동, 돌진 대형 등은 새로운 `SquadOrder`와 슬롯 계산 방식으로 확장할 수 있다.

## 12. 한계 및 개선 방향

현재 시스템은 전술 구조를 검증하는 데 초점을 맞추고 있으므로 몇 가지 개선 여지가 있다.

첫째, 포위 슬롯 배정은 greedy nearest-slot 방식을 사용한다. 이 방식은 계산이 빠르지만 전체 이동 거리의 전역 최적해를 보장하지는 않는다. 향후 Hungarian algorithm과 같은 최적 매칭 알고리즘을 적용하면 전체 이동 거리나 경로 교차를 더 줄일 수 있다.

둘째, 현재 시나리오는 플레이어 1명을 기준으로 주로 검증되었다. 다수 플레이어 환경에서는 플레이어 군집화 결과에 따라 경계 및 각개격파 전술이 더 적극적으로 사용될 수 있으므로, 다수 플레이어 시나리오를 추가해 검증할 필요가 있다.

셋째, 개별 NPC의 이동은 단순한 벡터 기반 이동을 사용한다. 장애물이 있는 환경으로 확장하려면 A* 또는 NavMesh 기반 경로 탐색과 결합할 필요가 있다.

넷째, 전술 선택은 현재 규칙 기반으로 구현되어 있다. 향후에는 플레이어 행동 패턴, Squad별 피해량, 전장 위치 등을 추가로 고려하여 더 다양한 전술 선택이 가능하도록 확장할 수 있다.

## 13. 결론

본 프로젝트에서는 중간보스 지휘 기반의 Tactical NPC 시스템을 설계하고 구현하였다. 시스템은 `PlatoonLeader`, `TacticalSquad`, `TacticalNpc`의 3계층 구조로 구성되며, 중간보스가 전술 판단을 수행하고 Squad가 대형 슬롯을 계산하며 개별 NPC가 FSM으로 행동을 실행한다.

시뮬레이션 초기에는 Squad 단위의 BoxAdvance 대형을 통해 NPC들이 조직적으로 배치되고, 대형 완료 후 플레이어를 추적한다. 전투가 진행되어 중간보스 체력 또는 Squad 생존 비율 조건이 충족되면 포위 전술이 발동되며, NPC들은 Squad별 섹터에 따라 계산된 원형 슬롯으로 이동한다.

이를 통해 단순 추적 기반 NPC보다 더 조직적이고 전술적인 전투 양상을 구현할 수 있었다. 또한 전술 판단, 대형 계산, 개별 행동을 분리한 구조는 향후 새로운 전술과 더 복잡한 전투 상황으로 확장하기에 적합하다.

## 부록 A. 핵심 수식 요약

타겟 선택:

```text
S(p) = 0.5 * 1 / (1 + ||B - p||)
     + 0.5 * (1 - HP(p) / HPmax(p))
```

전술 발동:

```text
HPboss / HPboss,max < 0.70
or
aliveSquadMembers / initialSquadMembers < 0.80
```

BoxAdvance Squad 중심:

```text
f = normalize(P0 - B)
r = (-fz, 0, fx)
C_s = P0 - f * d_approach + r * offset_x - f * offset_z - f * halfDepth
```

포위 섹터:

```text
sectorSpan_s = 2π * n_s / N
sectorAngle_s = angleAccum + sectorSpan_s / 2
```

포위 슬롯:

```text
theta_i = sectorAngle_s - sectorSpan_s / 2 + (i + 0.5) * sectorSpan_s / n_s
slot_i = P + R * (cos(theta_i), 0, sin(theta_i))
```

도착 판정:

```text
arrived_i = ||pos_i - slot_i|| < separationRadius * 0.25
```
